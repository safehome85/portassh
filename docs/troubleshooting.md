# Устранение неполадок

Набрано на живой эксплуатации (см. CHANGELOG 1.0.0). Проверено на
Windows 10 Pro x64 за занятым Kaspersky.

## `fork/exec cmd.exe: Access is denied` (плавающий)

**Причина:** антивирус троттлит серию дочерних процессов от неподписанного exe.
Снимается за 10–30 с само; portassh ретраит spawn 3 раза с паузой 3 с.

**Решения:**
- Добавьте exe в **«Доверенные приложения»** антивируса с галкой
  «Не ограничивать активность приложения» — обычные «Исключения»
  поведенческий детект не отключают
- Радикально — код-подпись (в build.sh есть условный шаг: `sign.pfx` + `SIGN_PASS`)
- Диагностика: попытки и причина пишутся в `portassh.log`; при окончательной
  неудаче клиент получает exit **127**

## Туннель умер и не поднимается

1. Проверьте `portassh.log`: стек паники означает баг (заведите issue);
   тишина перед обрывом — вероятен kill со стороны антивируса
2. Reconnect работает в бесконечном цикле (backoff 5→30 с). Если exe жив —
   он восстановит туннель максимум за ~1 минуту
3. Порт 2200 «refused» в первые ~60 секунд после падения — это призрак старой
   sshd-сессии на relay: экземпляр перескочит на 2201 и перерегистрируется.
   Текущий порт смотрите в `pconnect-list` (реестр на relay) или в
   `portassh_connection.txt`
4. На relay стоит настроить `ClientAliveInterval 30` + `ClientAliveCountMax 2`
   в sshd_config — мёртвые сессии освобождают порты за минуту

## Кириллица в выводе — кракозябры

Вывод cmd/powershell декодируется из CP866 в UTF-8 автоматически. Если видите
кракозябры:

- Убедитесь, что терминал клиента в UTF-8 (`locale` / настройки терминала)
- Вывод утилит, самостоятельно отдающих UTF-8 (не через OEM), будет
  перекодирован дважды — известный компромисс, см. `oem_windows.go`

## Слэши в командах

С версии 1.0.0 строка доходит до cmd дословно: одиночный `\` — как `\`.
Экранируйте как в обычной cmd-сессии на этой машине.

## Лимит длины команды (8191 символов)

Ограничение cmd.exe на аргументы. Длинные скрипты и данные передавайте
файлами:

```sh
scp -o ProxyJump=root@<relay> -P 2200 script.ps1 anyuser@localhost:
ssh -J root@<relay> -p 2200 anyuser@localhost "powershell -File script.ps1"
```

stdin exec-канала проброшен в процесс: `ssh -J ... "cmd /c more > file" < local`

## GUI-процесс с UAC-диалогом держит exec

`Start-Process -Verb RunAs` без `-Wait` возвращает управление сразу; если
процесс всё равно висит — запускайте через `start ""` (детач от консоли).
Принудительного таймаута exec в portassh нет намеренно.

## Две машины на одном relay

Каждая берёт свободный порт: первая 2200, вторая 2201 и т.д. (до 100).
Роли и порты видны в реестре `online.txt` на relay. Чтобы порт 2200
освободился за минуту после некорректного выключения машины, настройте
на relay `ClientAliveInterval 30` / `ClientAliveCountMax 2`.

## Диагностика на relay

```sh
ss -tlnp | grep -E ':22[0-9]{2}'     # слушатели пробросов
ps aux | grep 'sshd: portassh'       # живые сессии
tail -20 /home/portassh/online.txt   # реестр машин
```
